### 重現方式

```sh
node --experimental-strip-types --test --test-name-pattern=INT-07 Tests/integration.test.ts
```

1. 記憶體儲存先成功保存 `fresh()`，其中 `card=false`。
2. 經 `act` 取得門禁卡，記憶體遊戲狀態變為 `card=true`。
3. 儲存替身開始拒絕 `setItem`，模擬瀏覽器配額滿；讀取仍正常。
4. `save(current)` 回報「本機儲存失敗，請使用『匯出存檔』保留進度」。
5. `exportSave(current)` 實際優先回傳舊的 SAVE 原文，結果 `card=false`。

預期：使用者依警告匯出時，檔案可保留目前最新遊戲進度。實際：舊檔可以解析但漏掉剛取得的門禁卡。這個案例用公開函式與儲存替身重現；未宣稱已使真實瀏覽器配額耗盡。

可核對的失敗訊息：

```text
INT-07｜儲存配額滿後匯出，必須包含尚未成功寫入的最新進度
AssertionError: 匯出救援應保留剛取得的門禁卡
false !== true
```

證據是 [原始測試輸出](integration-tests.txt)，不是畫面操作問題，因此不以遊戲截圖代替重現。MW 修復時也要確認損壞原文仍可保留／取得，避免只修最新進度卻破壞既有排查流程。
